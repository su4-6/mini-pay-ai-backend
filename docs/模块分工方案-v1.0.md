# MiniPay AI 后端模块分工方案 v1.0

> **原则：** 按功能模块拆分，不按人员拆分。每个模块有独立交付边界、测试标准和验收入口。
> **排除：** `agent-service`（AI 模块）、`commerce-service`（P1 外卖）本期不开发。
> **基准：** `C:\java\mini-pay-ai-backend` 实际代码骨架 + PRD v1.4.1。

---

## 模块总览

```
M1 安全基线 ─────────────────────────────────────────────（基础层，所有模块依赖）
│
├── M2 消费者身份 ───────────────────────────────────────（identity-service）
│
├── M3 钱包与账本 ───────────────────────────────────────（wallet-service A/B）
│
├── M4 转账核心 ─────────────────────────────────────────（payment-service）
│
├── M5 支付与退款 ───────────────────────────────────────（payment-service）
│
└── M6 后台管理 ─────────────────────────────────────────（payment-service + BFFs）
```

| 模块 | 服务 | 优先级 | 估算工作量 | 可并行 |
|---|---|---|---|---|
| M1 | identity + BFFs | Must（最先） | 5 天 | 否，基础依赖 |
| M2 | identity-service | Must | 5 天 | 依赖 M1 完成 |
| M3 | wallet-service | Must | 5 天 | 依赖 M1 完成 |
| M4 | payment-service | Must | 6 天 | 依赖 M1/M2/M3 接口契约 |
| M5 | payment-service | Must | 5 天 | 依赖 M4 领域对象 |
| M6 | payment + BFFs | Should | 6 天 | 依赖 M4/M5 数据 |

### 核心业务规则
- 首次开户发放 ¥10,000.00（`BR-01`），Inbox 去重，绝不重复发放
- 充值单笔 ≤ ¥10,000.00，充值后余额 ≤ ¥20,000.00（`BR-06`）
- 接收站内转账不受 ¥20,000.00 上限拦截
- TCC 三阶段幂等键 `(xid, branchId, actionName)`，Confirm/Cancel 可无限重试
- 账务事务 `debitTotal = creditTotal`（数据库 CHECK 约束 + 应用层校验）
- 分录不可修改/删除，纠错只能冲正

### 完成判定
- [ ] 新用户开户后 availableAmountCent == 10,000,000（分）
- [ ] 重复消费 `user_registered` 不重复开户
- [ ] TCC Try 余额不足时拒绝（不抛异常，返回失败状态）
- [ ] TCC Confirm 重复调用幂等（不重复扣减/入账）
- [ ] TCC Cancel 先于 Try 时写空回滚栅栏，后续 Try 被拦截（防悬挂）
- [ ] 每笔账务 `debitTotal == creditTotal`
- [ ] 账单按 owner 过滤，不可跨用户查询

### TCC 全局事务流程
```
PaymentService (@GlobalTransactional)
  ├── Wallet A DebitAccountTccAction.try()     → 冻结付款方余额
  ├── Wallet B CreditAccountTccAction.try()    → 预留收款方入账
  └── TransferOrderTccAction.try()             → 创建 PROCESSING 订单
       ↓ 全部 try 成功
  ├── Wallet A DebitAccountTccAction.confirm() → 扣减冻结 + 借记账
  ├── Wallet B CreditAccountTccAction.confirm()→ 入账 + 贷记账
  └── TransferOrderTccAction.confirm()         → SUCCESS + 发布事件
       ↓ 任一 try 失败
  ├── Wallet A DebitAccountTccAction.cancel()
  ├── Wallet B CreditAccountTccAction.cancel()
  └── TransferOrderTccAction.cancel()          → FAILED + 发布事件
```

### 转账状态机
```
PENDING_CONFIRM → PROCESSING → SUCCESS
                 ↘ CANCELLED   ↘ FAILED
```

- [ ] TC-TRANSFER-002：金额非法/余额不足/超限 → 不可提交
