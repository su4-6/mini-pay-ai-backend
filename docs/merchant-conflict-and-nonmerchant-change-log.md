# 商户融合冲突处理与非商户模块改动清单

## 合并结论

- 已删除第二套 `com.minipay.payment.merchant` 聚合，能力并入主线商户、应用、订单模型。
- 保留主线运营路由、商户列表、应用列表与已有测试；未创建第二套运营入驻页面。
- 迁移冲突通过重编号解决：Identity V12；Payment 运营 V14--V19，商户能力 V20。没有覆盖或删除主线结构。

## 非商户模块的必要兼容改动

| 模块 | 改动 | 原业务是否改变 | 回滚边界 |
| --- | --- | --- | --- |
| Identity | 商户密码凭据、密码认证接口、商户 OAuth scope、演示账号 | 普通用户登录、实名、钱包开户不改变 | 移除商户密码入口和 V12 前先清理新凭据 |
| Management BFF | 商户独立 session 的登录、登出、密码代理 | 运营 session 与运营路由不改变 | 仅回滚 MerchantSessionController 的商户路径 |
| Payment | 订单增加服务端写入商户归属、扫码凭证、看板/回调 Inbox | 非商户订单路径保持原逻辑 | 回滚 V20 前先停止 B 端接口与回调消费 |
| Wallet | 两个内部、幂等的商户支付/退款记账入口 | 充值、提现、转账和原退款入口不改变 | 停用 Payment 的商户记账调用后可单独移除 |
| 运营端 | 使用主线商户/应用审批补齐入驻、通知和人工重试 | 没有将商户 B 端页面移入运营端 | 可按运营组件独立回退，不影响商户 Web |
| C 端 | 只扩展 API 支持经营码 resolutionId | 未修改 C 端 Android/H5 页面 | 不再提交 resolutionId 即走既有个人码流程 |

## 特别修正

- 修复内部按 owner 查询接口曾错误执行停用操作的问题：现为纯查询。
- 商户密码不再由 Payment 保存或校验，避免身份服务反向调用 Payment。
- 商户共享商家个人钱包，不再引入重复的商户钱包表或余额。
