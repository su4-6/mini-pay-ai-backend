# 商户 B 端需求追踪矩阵（v5.0.0）

> 本文件替代历史 v4.x 追踪记录。以《商户 B 端融合业务逻辑说明 v5.0.0》为准；历史文档中“提交即创建商户”“一人一商户”“商户独立钱包”及旧事件名不再作为验收规则。

| 业务条目 | 最终实现 | 数据与边界 | 验收证据 |
| --- | --- | --- | --- |
| 商家、多商户 | Identity 用户可拥有多个 merchant；`owner_user_id` 是普通索引 | 订单、应用、看板始终按 merchant 隔离；钱包按 owner 聚合 | 两个已审核商户种子及越权测试 |
| 入驻审核 | 提交仅写 `merchant_apply`；运营通过后才建 ACTIVE 商户 | 同店名未结束申请唯一；补件、拒绝、重提均审计 | 申请、审批、重提接口与运营待办 |
| 登录与安全 | 商户密码由 Identity 保存（Argon2id），短信、图形验证码、重置均在 Identity 完成 | 连续 5 次失败锁 10 分钟；B 端会话与运营端独立 | Identity、BFF 单元测试；登录页面不刷新 |
| 初始化与应用 | 每个商户一次默认应用与默认经营码；加应用走运营审批 | 行锁保护；密钥密文保存，只能一次领取或重置 | 初始化并发、密钥一次性、应用审批测试 |
| 经营码 | 每应用一条随机 token 二维码，可启停、换码 | 二维码不含金额、店主 ID 或密钥；旧 token 换码即失效 | 扫码解析、版本冲突、停用测试 |
| C 端建单 | `scan-resolution` 返回一次性 resolution；建单由服务端写 merchant/app/orderNo | 不信任客户端 merchant/app 归属字段；resolution 只能消费一次 | 篡改、过期、重复消费测试 |
| 支付、退款、钱包 | 支付/退款用钱包内部幂等接口完成资金闭环 | 商户不设独立钱包，收入/退款进出店主个人钱包；余额不足退款失败 | 三渠道支付、全额退款、账单核对 |
| 订单与看板 | B 端只读订单、详情、全额退款入口；看板按上海时区投影 | 事件为 `payment.order.succeeded`、`payment.refund.succeeded` | 7/30 天、今日、累计、渠道占比 |
| 回调 | 支付与退款各自签名串，HMAC-SHA256，最多 10 次退避重试 | 独立 Inbox 去重；人工重试不清零；仅保存响应摘要 | callback-mock 的成功、500、超时、重复投递 |
| 前端 | 独立路由与 MerchantShell；布局与运营端一致 | 中文化状态/错误码；二维码、订单抽屉、独立钱包页 | typecheck、build、人工验收手册 |

## 迁移与数据规则

- 所有新增结构仅以增量 Flyway 迁移 `V20__merchant_platform_capabilities.sql` 补齐；不删除主线表、字段或历史数据。
- Identity 的冲突迁移重编号为 V12；Payment 的运营迁移为 V14--V19，商户能力为 V20。
- 数据库使用 `utf8mb4`；数据库保存稳定英文枚举，页面和接口提示统一映射为中文。
- 演示数据来自 `demo-auth,demo-data` Profile 的 repeatable migration，不能再执行历史 `merchant_credential` 手工脚本。
