> **前提：** AI 模块 (`agent-service`) 本期不开发。`commerce-service`（P1 外卖）维持现状，不纳入任何人的工作范围。

## 分工总览

| 角色 | 负责服务 | 核心主题 | 关键复杂度 |
|---|---|---|---|
| **P1** | identity-service | 认证与安全基线 | OAuth 2.1 授权服务器、密码学、令牌轮换 |
| **P2** | wallet-service (A/B) | 钱包与复式账本 | 双物理库、TCC 分支、借贷平衡 |
| **P3** | payment-service（交易核心） | 转账/支付/退款编排 | TCC 全局事务编排、状态机、幂等 |
| **P4** | consumer-bff + management-bff + payment-service（管理域） | BFF 网关 + 后台管理 | 双 BFF 安全会话、商户/运营 CRUD、审计 |

## P1: 身份与安全基线（identity-service）

**负责目录：** `services/identity-service/`

**当前骨架：**
- `IdentityServiceApplication.java` — 启动类
- `SecurityConfiguration.java` — 默认拒绝策略
- Flyway: `V1__technical_messaging_tables.sql` (outbox/inbox), `V2__identity_core_tables.sql` (user_profile, user_credential, payment_authorization)

**待开发（按四层拆分）：**

### interfaces/rest
- `POST /auth/consumer/code/send` — 发送短信验证码（演示固定 `123456`，60s 倒计时，单手机号/IP 限流）
- `POST /auth/consumer/code/verify` — 验证码校验 + 登录/注册（5 次上限，10 分钟锁定）
- `POST /auth/web/register` — Web 用户名+密码+手机号注册
- `POST /auth/web/login` — Web 用户名+密码登录（失败不暴露账户存在性）
- `POST /security/pay-password` — 设置/修改 6 位支付密码（修改前先验证验证码）
- `POST /payment-authorizations` — 创建一次性支付授权令牌（60 秒、绑定用户/意图/金额/设备）
- `GET /users/recipients?keyword=` — 收款人搜索（最多 10 条脱敏候选）
- OAuth 2.1 / OpenID Connect 端点（Spring Authorization Server）
- 所有接口 Problem Details (RFC 9457) 错误响应

### application
- 验证码发送/校验用例（Redis 存储摘要、频率限制）
- 消费者注册/登录用例（首次注册触发 `user_registered` Outbox 事件）
- Web 注册/登录用例
- 支付密码设置/修改用例（Argon2id 哈希，与登录密码隔离）
- 支付授权令牌签发/消费用例
- 收款人搜索用例
- Token 轮换与复用检测用例

### domain
- `User` 聚合（user_id, login_name, phone_hash, nickname, status）
- `UserCredential` 实体（密码哈希、失败次数、锁定状态）
- `PaymentAuthorization` 实体（令牌哈希、绑定意图/金额/设备、过期/消费状态）
- `UserSession` 实体（refresh_token 摘要、过期、撤销）
- 角色/权限领域服务
- 领域事件：`UserRegistered`

### infrastructure
- MyBatis Mapper/PO（user_profile, user_credential, payment_authorization）
- Spring Authorization Server 配置（JWK、issuer、audience、RS256）
- Redis 验证码/限流/会话存储
- Argon2id 密码编码器
- Outbox 发布器（`user_registered` 事件）
- 安全配置：Resource Server、CORS、CSRF

**数据库表（已完成迁移）：** `user_profile`, `user_credential`, `payment_authorization`
**待新增迁移：** `user_session`, `role`, `permission`, `principal_role`

**验收关联：** AC-01, TC-AUTH-001 ~ TC-AUTH-005
**PRD 需求：** FR-APP-01-01, FR-APP-02-01, FR-COM-PASSWORD-01, FR-WEB-AUTH-01

## P3: 支付与转账核心（payment-service 交易域）

**负责目录：** `services/payment-service/`

**当前骨架：**
- `PaymentServiceApplication.java` — 启动类
- `TransferOrderTccAction.java` — 转账订单 TCC 骨架

**待开发（按四层拆分）：**

### interfaces/rest
- `POST /transfers/prepare` — 创建转账意图（校验收款人、金额、本人拦截、风险决策）
- `POST /transfers/{intentId}/confirm` — 确认转账（校验 paymentAuthToken、幂等键、启动 TCC 全局事务）
- `POST /transfers/{intentId}/cancel` — 取消转账意图
- `GET /transfers/{transferNo}` — 查询转账订单详情
- `/openapi/v1/payments` — 创建支付订单（模拟通道）
- `/openapi/v1/payments/{payOrderNo}` — 查询支付订单
- `/openapi/v1/refunds` — 创建退款（仅全额）
- `/openapi/v1/refunds/{refundOrderNo}` — 查询退款
- `/internal/v1/transfer-orders/try|confirm|cancel` — 转账订单 TCC 分支（Payment 自身作为 TCC 参与者）

### application
- 转账意图 Prepare 用例（收款人校验、金额边界、本人拦截、风险决策、过期时间）
- 转账确认用例（验证 paymentAuthToken 绑定关系、幂等键、TM 启动 TCC 全局事务）
- 转账取消用例
- 支付订单创建/查询用例（模拟通道直接成功）
- 退款创建用例（校验原订单状态、全额退款、不可重复）
- 回调处理用例（幂等入库、状态机迁移）
- TCC 全局事务编排（协调 Wallet A Try → Wallet B Try → TransferOrder Try → 全部 Confirm 或全部 Cancel）
- Seata 恢复任务（PROCESSING 状态对账、推进到终态）
- 过期意图自动取消定时任务

### domain
- `TransferIntent` 聚合（intent_no, payer, receiver, amount, risk_decision, status: PENDING_CONFIRM/CANCELLED）
- `TransferOrder` 聚合（transfer_no, client_request_id, intent_id, xid, status: PROCESSING/SUCCESS/FAILED, failure_code, version）
- `PaymentOrder` 聚合（pay_order_no, app_id, merchant_order_no, amount, channel, status, version）
- `RefundOrder` 聚合（refund_order_no, pay_order_id, merchant_refund_no, amount, status, version）
- 收款人搜索领域服务（脱敏、最多 10 条）
- 转账状态机（PENDING_CONFIRM → PROCESSING → SUCCESS/FAILED）
- 退款状态机（REFUND_PROCESSING → REFUNDED/REFUND_FAILED）
- 幂等键处理（client_request_id 唯一约束）

### infrastructure
- MyBatis Mapper/PO（transfer_intent, transfer_order, payment_order, refund_order）
- Seata TCC 全局事务发起（@GlobalTransactional）
- TransferOrderTccAction 实现（Try: 创建/锁定订单; Confirm: 标记成功+发布事件; Cancel: 标记失败+发布事件）
- Client Credentials 调用 Wallet `/internal/v1` 和 Identity `/internal/v1`
- 模拟支付通道实现（支付即成功/退款即成功）
- Outbox 发布器（transfer_succeeded/failed, refund_succeeded/failed 等事件）
- 回调 HTTP 客户端（mock 通道回调）
- 恢复定时任务（Spring Scheduler / Quartz）

**数据库表（已完成迁移）：** `transfer_intent`, `transfer_order`, `payment_order`, `refund_order`
**待新增迁移：** `callback_record`, `collection_code`

**验收关联：** AC-02, AC-03, AC-05, AC-06, TC-TRANSFER-001 ~ TC-TRANSFER-008, TC-REFUND-001 ~ TC-REFUND-004
**PRD 需求：** FR-APP-TRANSFER-01, FR-WEB-TRANSFER-01

## 依赖关系与开发顺序

```
P1 (Identity) ──┬──> P3 (Payment 交易核心) ──> P4 (BFF + 管理域)
                │
P2 (Wallet)  ──┘
```

| 阶段 | 周次 | P1 | P2 | P3 | P4 |
|---|---|---|---|---|---|
| 安全基线 | 第 1 周 | OAuth Server + 登录/注册 | 双数据源 + 钱包查询/充值 | — | — |
| 身份+钱包 | 第 2 周 | 支付密码 + 支付授权 + Outbox | TCC Try/Confirm/Cancel + 账本 | 转账意图 Prepare | BFF OAuth Client 配置 |
| 转账联调 | 第 3 周 | 收款人搜索 + 令牌消费 | 账单投影 + 恢复任务 | TCC 编排 + Confirm/Cancel + 状态机 | BFF 路由代理 |
| 支付+后台 | 第 4 周 | 集成修复 | 集成修复 | 支付/退款 + 回调 | 商户/运营 CRUD + 审计 + 沙箱 |
| 联调验收 | 第 5 周 | 安全测试 | TCC 回归测试 | 契约测试 | 权限/UI 测试 |

**并行策略：**
- 第 1 周：P1 + P2 完全并行（无代码依赖，通过事件契约解耦）
- 第 2 周：P1 + P2 继续；P3 启动（依赖 P1 paymentAuthToken 接口契约、P2 TCC 分支接口契约）
- 第 3 周：四人全并行；P4 启动 BFF（依赖 P1 OAuth Client 配置）
- 第 4-5 周：四人全并行；集成联调

## 跨团队协作契约

### 服务间接口（需提前对齐）

| 调用方 | 被调用方 | 接口 | 负责人交付 |
|---|---|---|---|
| P3 Payment | P2 Wallet | `/internal/v1/tcc/{debit\|credit}/{try\|confirm\|cancel}` | P2 先提供接口签名 + 空实现 → P3 可并行开发 |
| P3 Payment | P1 Identity | `/internal/v1/payment-authorizations/verify` (验证 paymentAuthToken) | P1 先提供接口签名 |
| P2 Wallet | P1 Identity | `user_registered` 事件 (RabbitMQ) | P1 定义事件 schema |
| P4 BFF | P1 Identity | OAuth Client 注册 | P1 提供 client-id/secret |
| P4 BFF | P3 Payment | 所有 `/api/v1` 代理端点 | 按 contracts/openapi/ 契约文件 |

### 事件契约（P1 → P2）

  "traceId": "otel-trace-id",
  "payloadVersion": 1,
  "payload": {
    "userId": "uuid-v7",
    "loginName": "demo_user",

### 公共规范（全员遵守）

1. 四层依赖方向：`interfaces → application → domain`；`infrastructure` 实现 `application/domain` 端口
2. `domain` 层纯 Java，不依赖 Spring/MyBatis/Seata
3. 服务间不建立 Maven 依赖；契约以 `contracts/openapi/` 和 `contracts/asyncapi/` 为准
4. 金额统一 `long/BIGINT` 分单位（`_amount_cent`）；时间 `Instant` + UTC `DATETIME(6)`；主键 UUIDv7 `BINARY(16)`
