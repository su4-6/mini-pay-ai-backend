## 一、系统总览

### 1.1 服务清单

| 服务 | 端口 | 职责 | 数据库 | 现状 |
|---|---|---:|---|---|
| identity-service | 8081 | OAuth/OIDC、登录、用户、RBAC、支付授权 | `minipay_identity` | 完整实现 |
| payment-service | 8082 | 支付/退款/转账/充值/提现、商户域、运营看板 | `minipay_payment` | 完整实现 |
| wallet-service（a/b 两分片） | 8083/8084 | 单一 CNY 钱包库、账本、冻结、Seata TCC | `minipay_wallet_a/b` | 完整实现 |
| agent-service | 8086 | AI 会话（预期）/ 聊天 CRUD（实际） | `minipay_agent` | **脚手架**，AI 能力未实现 |
| consumer-bff | 8087 | 消费者安全会话（预期） | 无 | **脚手架**，仅 CSRF+健康检查 |
| management-bff | 8088 | 运营端+商户端 BFF 代理 | 无 | 完整实现 |
| 基础设施 | 3306/6379/5672/8091 | MySQL / Redis / RabbitMQ / Seata | — | — |

技术栈：Java 21、Spring Boot 3.5、Spring Authorization Server、MyBatis（identity/payment）/ JdbcTemplate（wallet/agent）、Flyway、RabbitMQ（Outbox/Inbox）、Seata TCC、Alibaba OSS（可选）。

### 1.2 部署形态

- 全部服务通过 `docker compose`（项目名 `minipay`）容器化运行，`compose.yaml` 中所有 app 容器内监听 **8080**（`SERVER_PORT=8080`），映射到宿主各端口。
- wallet-service 部署 **两套物理分片**（a/b），各自独立 DB 与 Seata application-id（`wallet-service-A/B`），为未来水平分片预留；见「四、钱包服务」。
- MySQL 用 docker `mysql` 服务（root/minipay）；本机原生 MySQL80 与 MiniPay 无关（详见仓库根 README 及 `.env` 说明）。

## 二、身份服务 identity-service（8081）

### 2.1 OAuth2/OIDC 授权服务器

启动时 `managementClientBootstrap`（`infrastructure/security/SecurityConfiguration.java`）对全部客户端做 **find-or-update**（先删后插 `oauth2_registered_client`）。

| client_id | 认证方式 | 授权类型 | audience | 主要 scope | access/refresh TTL | 用途 |
|---|---|---|---|---|---|---|
| `minipay-management-bff` | client_secret_basic | auth_code + refresh | `management-api` | ops.portal / ops.*.read / ops.*.write / payment.refund.write | 10m / 8h | 运营平台 |
| `minipay-android` | public (PKCE) | auth_code + refresh | `consumer-api` | identity.profile.* / payment.* / wallet.read / agent.conversation | 10m / 30d | 原生 App |
| `minipay-merchant-bff` | public (PKCE) | auth_code + refresh | `merchant-api` | merchant.portal.* / payment.collection-code.read / wallet.read | 10m / 30d | 商户端 |
| `minipay-payment-to-identity` | client_secret_basic | client_credentials | `identity-internal` | identity.payment-authorization.verify / identity.account.manage | 5m | payment 调 identity |
| `minipay-payment-to-wallet` | client_secret_basic | client_credentials | `wallet-internal` | wallet.tcc / wallet.account.resolve / wallet.posting.write | 5m | payment 取钱包令牌 |
| `minipay-agent-to-payment` | client_secret_basic | client_credentials | `payment-internal` | payment.tool.invoke | 5m | Agent→payment（预留） |
| `minipay-identity-to-payment` | client_secret_basic | client_credentials | `payment-internal` | payment.tool.invoke | 5m | identity→payment（注册用） |

- 内部客户端默认 secret 均为 `-demo-secret`（demo 环境）。
- **JWT**：签发用 RSA（生产必配 `JWT_SIGNING_*_KEY_LOCATION`；demo-auth 才允许运行时生成临时密钥）；access token 注入 audience、`roles`、`user_id`、`display_name`，消费者另含 `pay_password_set`/`onboarding_completed`/`real_name_status`/`real_name_verified`/`device_id`。
- **Token 落库摘要化**：authorization/access/refresh/id token 用 `token-digest-pepper` HMAC-SHA256 摘要后存储（前缀 `hmac-sha256:`），不存明文。
- **Refresh token 族防重放**：`oauth2_refresh_token_family`（ACTIVE/REVOKED）+ history；发现 TOKEN_REUSE 即 revoke 整族。
- **密码编码**：Argon2id。

### 2.2 登录方式

| 端 | 方式 | 流程 | 关键规则 |
|---|---|---|---|
| 运营端（HTML `/login`） | 密码登录 | `POST /login/password`（phone+password+captcha） | 5 次失败锁 15 分钟；须 `platform_admin` 角色；防枚举用固定 dummy hash 恒时比较 |
| 运营端 | 短信登录 | `POST /login/sms`（phone+challengeId+smsCode） | 先图形验证码，仅 eligible admin 才发码 |
| 消费者（App） | 短信码 | `POST /api/v1/auth/consumer/code/send` + `/code/verify` | 60s 防重发、错 5 次锁 10 分钟；**首次登录幂等开户**并发 `identity.user.opened` 事件；直接签发授权码（绕过 authorize 页） |
| 商户端 | 短信码 | `POST /api/v1/auth/merchant/code/send` + `/code/verify` | 需图形验证码；PKCE |
| 商户端 | 密码 | `POST /api/v1/auth/merchant/password/verify` | 需图形验证码；`MERCHANT_LOGIN_PASSWORD` 凭据，5 次锁 10 分钟 |

- **图形验证码**：4 位（去易混淆字符），HMAC 摘要存 Redis，TTL 2 分钟，一次性。
- **短信挑战**：6 位码，TTL 5 分钟；demo profile 固定码 `DEMO_SMS_CODE=123456`（`DemoSmsSender`，不真实发送）。
- **商户改密**：`PUT /password`（当前密码校验）与 `PUT /password/reset`（短信前置）。新密码规则 **12-20 位、字母+数字**（⚠️ 与 `docs/local-debug-acceptance.md` 写的"6-20 位"不一致，以代码为准）。
- **支付密码**：`PUT /api/v1/users/me/payment-password`，仅 6 位数字，独立于登录密码，`INSERT IGNORE` 防重复（`PAYMENT_PASSWORD_ALREADY_SET`）。

### 2.3 用户域

- **`user_profile`**：`user_id`(BINARY16)、`login_name`(唯一)、`minipay_no`(`MP`+20 hex，唯一)、`phone_hash`(HMAC 唯一)、`phone_masked`、`nickname`(默认"米灵用户")、`avatar_object_key`、`status`、`credential_type`(PASSWORD / SMS_ONLY)、`onboarding_status`(PENDING/COMPLETED)、`version`。
- **首次开户**：短信登录时 `findOrCreate` 幂等（`INSERT IGNORE`），发 `identity.user.opened` → wallet 开户。
- **onboarding**：`PUT /api/v1/users/me/onboarding`（Idempotency-Key 16-128 位），幂等键+request_hash 防重放，昵称 2-20 字，完成后 `onboarding_status=COMPLETED`。
- **商户 owner 账户**：`POST /internal/v1/accounts/merchant-owner`（payment 在 BD 代建/入驻审核通过时调用），find-or-create 幂等，SMS_ONLY 无密码账户 + 追加 `merchant_owner` 角色。
- **实名认证**：`POST /api/v1/real-name-verifications`（18 位身份证校验位+人脸 JPEG 魔数+Idempotency-Key），PROCESSING→VERIFIED/REJECTED。Provider：`disabled` / `sandbox`（证件尾数非 0 即过）/ `aliyun`。**支付授权强制实名**。
- **头像/资料**：`avatar_upload` PENDING→CONSUMED，OSS 预签名直传（TTL 10m），读 URL TTL 30m，定时清理；`PATCH /api/v1/users/me` 乐观锁（`PROFILE_VERSION_CONFLICT`）。
- **换绑**：换手机号（短信挑战）→ `PUT /phone`（`MOBILE_ALREADY_BOUND`）；绑/解绑邮箱。

### 2.4 支付授权（payment authorization）

- `POST /api/v1/payment-authorizations`（Idempotency-Key）：前置校验实名 → 校验支付密码（错 5 次锁 10 分钟）→ 生成 UUIDv7 authorizationId，**TTL 2 分钟**；token=Base64URL(authId)+HMAC(binding)；落库仅存 `token_hash`。
- subjectType：`TRANSFER_INTENT` / `PAYMENT_ORDER` / `WITHDRAWAL_ORDER` / `BANK_CARD_BALANCE_QUERY`（仅余额查询允许 0 金额）。
- 消费：`POST /internal/v1/payment-authorizations/verify-and-consume`（payment 调用），行锁+`MessageDigest.isEqual` 比对+原子置 consumed。

### 2.5 RBAC 与 scope 映射

- 角色：`platform_admin` / `merchant_admin` / `merchant_applicant` / `merchant_owner`；普通消费者无角色行。
- 端点→scope 授权（audience+scope 双重）：见「九、端点授权表」。
- 应用 API 层白名单制（`anyRequest().denyAll()`），CSRF 忽略认证/注册类路径。

### 2.6 消息事件

- 交换机 `minipay.events`（Direct，durable）；事务 Outbox 表 `outbox_event`，500ms 批捞（≤50，`FOR UPDATE SKIP LOCKED`，30s 租约），confirm 确认，失败指数退避最多 10 次后 DEAD。
- **发布**：`identity.user.opened`（aggregate `user`，payload `{userId}`）。
- **消费**：identity **不消费任何消息**。

## 三、支付服务 payment-service（8082）

### 3.1 支付单（payment order）

- 表 `payment_order`：`pay_order_id`、`pay_order_no`(唯一)、`app_id`、`merchant_order_no`、`payer_user_id`、`amount_cent`、`currency`(CNY)、`subject`、`channel`、`status`、`expires_at`(15min)、`annual_limit_mode`、`merchant_id`/`application_id`、`resolution_id`、`client_idempotency_key`、`authorization_id`。
- 关联表 `payment_attempt`（渠道单号 `CH`+id）。
- **支付方式**：`ALIPAY` / `WECHAT_PAY` / `WALLET_BALANCE`。外部渠道 redirect 为沙箱深链 `minipay://sandbox/...`。
- **状态机**：`PROCESSING` → `SUCCEEDED` | `FAILED`（创建金额 1..1,000,000 分；非 WALLET_BALANCE 须有效银行卡）。
- **确认**：
  - `confirmWalletBalance`：授权校验+消费（`identity.verifyAndConsume`）→ `wallet.debitPayment` → SUCCEEDED + 事件。
  - `completeSandboxExternal`：仅外部渠道，回调成功→记账+SUCCEEDED；失败→FAILED（`SANDBOX_CHANNEL_DECLINED`）。
- **商户/收款码支付**：带 `resolutionId` 扫码时锁行校验（商户/应用 ACTIVE、非本人支付、渠道可用）→ 消费 resolution → `wallet.postMerchantPayment`（付款人→商户主账户）。
- **`app_id`**：无商户时固定 `consumer-sandbox`；`merchant_order_no`：无商户=scopedKey，有商户=`M`+id。

### 3.2 充值 / 提现

- **充值** `recharge_order`：`create`（PROCESSING，幂等）→ `process`：`bank.debit`（卡扣款）→ `wallet.creditRecharge`；**钱包入账失败→`bank.refundDebit` 原路冲正**→FAILED（`WALLET_POSTING_REJECTED`）。成功→SUCCEEDED + `payment.recharge.succeeded`。
- **提现** `withdrawal_order`：`confirm` 先绑授权 → `wallet.debitWithdrawal` → `bank.payout`；**payout 失败→`wallet.reverseWithdrawal` 冲正**→FAILED；成功→`wallet.completeWithdrawal`+SUCCEEDED + `payment.withdrawal.succeeded`。

### 3.3 退款 —— **单笔全额**

- `refund_order`：`(pay_order_id, merchant_refund_no)` 唯一改为 **`pay_order_id` 唯一 → 每笔支付单最多一笔退款**（V9）。
- 规则：仅 SUCCEEDED 支付单可退；**非商户 P0/消费者支付仅支持 WALLET_BALANCE 方式退款**；**必须全额**（`amountCent == payment.amountCent`）。
- 钱包交互：无商户 `wallet.creditRefund`；有商户 `wallet.postMerchantRefund`（商户主账户→付款人）。
- 状态：PROCESSING→SUCCEEDED + `payment.refund.succeeded`。

### 3.4 转账（Seata TCC 编排）

- `transfer_intent`：`PENDING_CONFIRMATION` → `CONFIRMED` / `CANCELLED` / `EXPIRED`（15min）。禁止自转、金额 1..1,000,000、remark≤50、source ∈ FORM/AI/PERSONAL_COLLECTION_CODE、`risk_decision` 恒 'PASS'。
- `transfer_order`：`PROCESSING` → `SUCCEEDED` / `FAILED`。
- **`SeataTransferCoordinator`**（`@GlobalTransactional(name="wallet-transfer-v1", timeoutMills=10000)`）：
  1. 取 `RootContext.getXID()`（空则 `DISTRIBUTED_TRANSACTION_UNAVAILABLE`）；
  2. 未授权时 `identity.verifyAndConsume`（subjectType=TRANSFER_INTENT）→ 授权；
  3. intent 确认；`bindTransferXid`；
  4. `wallet.tryDebit`（拒收→`INSUFFICIENT_BALANCE`）、`wallet.tryCredit`（拒收→`RECEIVER_WALLET_REJECTED`）。
  - **Confirm/Cancel 由 Seata TC 回调 wallet 侧 TCC 分支**；payment 不手工推进二阶段。
- **恢复**：`TransferRecoveryJob` 每 2s 扫描 PROCESSING+已授权+到期+租约空闲的单 → resume → `executeOrReconcile`。`reconcile` 查 `wallet.transferOutcome`：双 CONFIRMED→SUCCEEDED；rolledback/单边取消→FAILED。
- ⚠️ `infrastructure/tcc/TransferOrderTccAction.java` 的 `@LocalTCC` 接口**无实现类**（占位）；真实分支在 wallet 侧。

### 3.5 商户域（B 端）

- **商户档案 `merchant`**：`merchant_no`（`M`+时间戳+6hex，唯一）、name 2..64、shortName 2..32、contactMobile（`^1[3-9]\d{9}$`）、merchantType（PERSONAL/INDIVIDUAL/ENTERPRISE）、mccCode、经纬度、shopImages、status（**ACTIVE/DISABLED/FROZEN**）、freezeReason、ownerUserId、source（OPS/ONBOARDING）、defaultApplicationId、initializedAt。
- **商户应用 `merchant_application`**：`app_id`（`mp_app_`+uuidhex，唯一）、name（商户内唯一）、app_type（SELF_USE/THIRD_PARTY）、is_default、**secret 加密落库**（AES/GCM）、notify_url/refund_notify_url（**必须 HTTPS**）、ip_white_list（CIDR）、api_permissions（默认 PAYMENT_CREATE/PAYMENT_QUERY/REFUND_CREATE/BILL_QUERY）、available_channels（WALLET/ALIPAY/WECHAT）、status（**创建默认 DISABLED**，须 ops 启用）、version。
- **密钥管理**：`viewApplicationSecret` **一次性领取**（二次报 `APPLICATION_SECRET_ALREADY_VIEWED`）；`resetApplicationSecret` 轮换（key_version+1）。
- **经营收款码 `merchant_collection_code`**：每应用一个，token=`mc_`+codeId+base64url(24B)，QR=`minipay://collect/merchant?token=`；`replaceCollectionCode` 轮换；应用禁用级联禁用收款码。
- **扫码解析 `merchant_scan_resolution`**：`resolve` 校验商户/应用/收款码状态（`MERCHANT_COLLECTION_UNAVAILABLE`）→ 建 resolution（expires 600s）→ 支付创建时幂等消费。
- **回调通知 `merchant_notification` + attempt**：每 5s 投递到期通知；HMAC-SHA256 签名头 `X-MiniPay-Timestamp/Nonce/Signature`；成功须 HTTP 200 + body `{"code":"SUCCESS"}`；最多 10 次指数退避；`POST /{id}/retry` 人工重试。
- **入驻 `merchant_apply`**：`DRAFT/PENDING/APPROVED/REJECTED/SUPPLEMENT`；submit→approve（建 ACTIVE 商户并回写 resultant_merchant_id）/reject/requestSupplement；**审核通过通知为 TODO 占位**。
- **应用申请 `application_apply`**：PENDING/APPROVED/REJECTED/SUPPLEMENT；approve→建应用（DISABLED）→置 THIRD_PARTY+下发 secret。
- **审计**：`merchant_operation_audit`（MERCHANT_OWNER/ADMIN 操作审计）+ 运营 `operation_audit`。

### 3.6 运营看板

- `GET /api/v1/ops/dashboard?range=7d|30d`：`platform_daily_metric` 聚合，successRateBasisPoints=成功*10000/提交；pending=超 15 分钟未终态单+FAILED 通知；activeMerchantCount=区间内有成功支付的商户。
- 投影：`DashboardProjectionService` 消费 `payment.order.succeeded` / `payment.refund.succeeded` 写 `platform_daily_metric` / `merchant_daily_metric`；商户看板来自 `merchant_daily_metric`。

### 3.7 事件

发布（routing key=eventType）：`payment.order.succeeded`、`payment.recharge.succeeded`、`payment.withdrawal.succeeded`、`payment.transfer.processing/succeeded/failed`、`payment.refund.succeeded`。
消费：`minipay.merchant.metric.v1`、`minipay.merchant.notification.v1` 队列（写 merchant_metric_inbox / merchant_notification_inbox → 投影 / 通知）。

### 3.8 对外调用

- **identity**：`IdentityInternalClient`（client `minipay-payment-to-identity`）→ `POST /internal/v1/payment-authorizations/verify-and-consume`；`IdentityServiceClient`（client 同）→ `POST /internal/v1/accounts/merchant-owner`。
- **wallet**（`WalletInternalClient`，client `minipay-payment-to-wallet`，`WALLET_BASE_URL`）：
  - `POST /internal/v1/wallet-accounts/resolve`
  - TCC：`POST /internal/v1/tcc/debits/try`、`/credits/try`（带 `X-Transaction-Xid` 头）、`/tcc/transfers/outcomes`
  - 记账：`/wallet-postings/{recharges,withdrawals,withdrawals/complete,withdrawals/reverse,payments,refunds,merchant-payments,merchant-refunds,opening-grants}`（Idempotency-Key）
  - 错误透传：`ANNUAL_OUTFLOW_LIMIT_EXCEEDED`、`MERCHANT_REFUND_INSUFFICIENT_BALANCE`；网络失败→`WALLET_POSTING_REJECTED`/`WALLET_TCC_UNAVAILABLE`。
- **seata**：`tx-service-group=minipay_tx_group` → `SEATA_SERVER_ADDR`（默认 localhost:8091）；`enable-auto-data-source-proxy=false`。

### 3.9 Demo 种子（demo-data）

4 商户（星河便利店 ACTIVE / 云帆咖啡 DISABLED / 青禾书店 ACTIVE / 远山餐厅 ACTIVE）、4 应用、1 笔 6880 分 SUCCEEDED 支付单、30 天看板数据、1 条 FAILED 通知。沙箱银行账户绑卡时动态创建（初始 ¥100,000）。

## 四、钱包服务 wallet-service（8083/8084）

### 4.1 钱包账户模型

- `wallet_account`：`account_no`(唯一，消费者=`W`+compact(userId))、`owner_type`(CONSUMER/SYSTEM)、`owner_id`、`currency`(CNY)、`account_role`(CONSUMER_WALLET/SANDBOX_ISSUANCE/TRANSFER_CLEARING/BANK_SETTLEMENT)、`available_amount_cent`、`frozen_amount_cent`、`status`(ACTIVE/SUSPENDED)、`version`。
- **不变式**：仅消费者账户 `available >= 0`；系统账户允许负余额（清算可能临时为负）；`frozen >= 0`。**没有 reserved 列**（"reserved"实际在 `annual_outflow_limit.reserved_amount_cent`）。
- **系统种子账户**（两分片相同）：`SYS_SANDBOX_ISSUANCE`（沙箱发行池，9e15）、`SYS_TRANSFER_CLEARING`（转账清算，V6 清零后从 0 累计）、`SYS-BANK-SETTLEMENT`（银行结算，9e15）。⚠️ 命名风格不一致（下划线 vs 连字符）。

### 4.2 账本 / 账单 / 幂等

- `ledger_transaction`（借贷平衡约束 `debit_total = credit_total`）+ `ledger_entry`（DEBIT/CREDIT 双分录），`business_type` 与借→贷对应：

| business_type | 借 | 贷 |
|---|---|---|
| OPENING_GRANT | SANDBOX_ISSUANCE | 消费者 |
| RECHARGE | BANK_SETTLEMENT | 消费者 |
| WITHDRAWAL | 消费者 | BANK_SETTLEMENT |
| WITHDRAWAL_REVERSAL | BANK_SETTLEMENT | 消费者 |
| PAYMENT | 消费者 | BANK_SETTLEMENT |
| REFUND | BANK_SETTLEMENT | 消费者 |
| MERCHANT_PAYMENT | 付款人（或外部渠道时 BANK_SETTLEMENT） | 商户主账户 |
| MERCHANT_REFUND | 商户主账户 | 付款人 |
| TRANSFER_OUT | 付款人 | TRANSFER_CLEARING |
| TRANSFER_IN | TRANSFER_CLEARING | 收款人 |

- `wallet_bill` 账单投影：`owner_id+business_type+business_no` 唯一；终态不可覆盖。⚠️ 转账账单 business_type 用 `TRANSFER`，与 ledger 的 `TRANSFER_OUT/IN` 口径不同。
- `wallet_posting_idempotency`：所有 posting 先抢占幂等键（并发重复返回复用结果），hash/type/no 不一致→`IDEMPOTENCY_KEY_REUSED`。
- 对账（每 10s）：不平衡账本、清算余额非 0、单边确认分支 → ERROR 告警。

### 4.3 冻结

- `account_freeze`：`(xid,branch_id)` 唯一 + `(business_no,account_id)` 唯一；状态 TRY/CONFIRMED/CANCELLED。
- **Try**：校验账户 ACTIVE → `LIMITED` 模式先预留年度额度 → `insertFreeze(TRY)` + `changeBalance(-amount, +amount)`（**available 减、frozen 增**）+ 插 PROCESSING 账单。
- **Confirm**：冻结清零、TRANSFER_CLEARING += amount、记账 TRANSFER_OUT、账单 SUCCEEDED、预留转已用。
- **Cancel**：解冻回 available、释放预留、账单 FAILED（TRANSFER_CANCELLED）、分支 CANCELLED；**分支不存在返回 true（空回滚幂等）**。

### 4.4 Seata TCC 分支（Debit/Credit）

- `@LocalTCC` + `@TwoPhaseBusinessAction(name="walletTransferDebitTccV1"/"walletTransferCreditTccV1", useTCCFence=true)` → 用 Seata 内置 `tcc_fence_log` 防悬挂/幂等（V5 手动栅栏表 V6 已 DROP）。
- **XID 透传**：`SeataXidPropagationFilter` 仅拦截 `/internal/v1/tcc/debits/try` 与 `/credits/try`，要求 `TX_XID` 头，bind 进 RootContext → LocalTCC 代理生成 branchId。
- **tryCredit 不动钱**，仅插 `pending_credit` TRY；`confirmCredit` 才 `TRANSFER_CLEARING -= amount`、收款人 += amount。
- **二阶段由 Seata TC 回调** wallet 的 confirm/cancel；wallet 无 HTTP confirm/cancel 端点。
- **年度流出限额**（V7，未绑定实名/未绑卡消费者）：`annual_outflow_limit`（limit 默认 20 万元，used/reserved）+ `annual_outflow_adjustment`（CONSUME/RELEASE 流水）；`used+reserved+amount <= limit` 否则 `ANNUAL_OUTFLOW_LIMIT_EXCEEDED`。模式：`LIMITED`（默认）/ `EXEMPT_ACTIVE_CARD`（绑卡豁免）。退款释放已用额度。

### 4.5 充值 / 提现 / 银行结算

- 充值：事件驱动 `postRecharge`（BANK_SETTLEMENT→消费者），**余额上限 `RECHARGE_BALANCE_CAP_CENT=200万`**（超限 `RECHARGE_BALANCE_LIMIT_EXCEEDED`），单笔上限 100 万。
- 提现：`postWithdrawal`（消费者→BANK_SETTLEMENT，账单 PROCESSING）→ `completeWithdrawal`（SUCCEEDED）/ `reverseWithdrawal`（冲正，重复幂等）。
- 开户：`openWallet`（OPENING_GRANT，送 `INITIAL_GRANT_CENT=100万`=¥10,000 沙箱演示金）。
- 声明：`SANDBOX_NOTICE` 明示所有银行/支付宝/微信均为模拟通道。

### 4.6 端点

- 消费者：`GET /api/v1/wallets/me`、`/wallets/me/bills`、`/wallets/me/bills/{billId}`（JWT 前置要求 onboarding_completed、real_name_verified）。
- 运营：`/api/v1/management/wallet/accounts/{id}`、`/ledger-transactions`、`/ledger-transactions/{id}`。
- 内部：`/internal/v1/wallet-accounts/resolve`、`/wallet-postings/*`（10 个记账端点）、`/internal/v1/tcc/debits/try`、`/credits/try`、`/transfers/outcomes`。
- 钱包**只消费不发布**事件（`minipay.wallet.p0-events` ← `identity.user.opened`、`payment.recharge.succeeded`）。

## 六、BFF 服务

### 6.1 consumer-bff（8087）—— 脚手架

**【占位/脚手架】** 仅 `GET /api/v1/csrf` + actuator 健康；其余 `denyAll()`。无 OAuth 登录、无代理。会话配置（`__Host-minipay-consumer`、Secure、HttpOnly）为未来消费者会话预留。

### 6.2 management-bff（8088）—— 完整实现

同时服务**运营端（ops-web 8000）**与**商户端（merchant-web 8001）**两个前端（dev 代理都指向 8088）。

**运营端 OIDC 登录**：
- `spring.security.oauth2.client.registration.minipay-ops`（client `minipay-management-bff`，PKCE，redirect `/login/oauth2/code/minipay-ops`）→ 成功后 302 到 `http://localhost:8000/`。
- 登出：写登出审计 → `POST /oauth2/revoke` 撤销 refresh → OIDC end_session 跳转。

**商户端登录（纯 API，无 OAuth 重定向）**：
- `POST /api/v1/merchant-auth/captcha`（取图形验证码）、`/code/send`（发短信）、`/code/verify`（短信登录）/ `/password/verify`（密码登录）→ BFF 用 **PKCE 生成 verifier + code→token 交换**，token 只存 WebSession，**前端拿不到明文 token**。
- 商户会话与运营 OAuth 会话**物理隔离**（商户登出不影响 ops 会话）。

**代理路由（业务逻辑全在上游，BFF 只鉴权+透传）**：

| Controller | 路径 | 上游 | 说明 |
|---|---|---|---|
| OpsPaymentProxyController | `/api/v1/ops/**` | payment | 运营主代理，Bearer 透传 |
| MerchantPaymentProxyController | `/api/v1/merchant-gateway/**` | payment（路径重写 `/api/v1/**`） | 商户同源中继 |
| MerchantWalletProxyController | `GET /api/v1/merchant-wallet/**` | wallet（`/api/v1/wallets/me/**`） | **只读**，非 GET→405 |
| LoginAuditProxyController | `/api/v1/login-audits` | identity | 登录审计 |
| MerchantSessionController | `/api/v1/merchant-auth/**`、`/merchant-session` | identity | 登录/会话/改密 |

- **双层鉴权**：BFF 校验角色+scope（运营按 `platform_admin` + ops.* scope），上游再校验 JWT audience+scope。
- 错误：上游问题透传；上游不可达→502 `UPSTREAM_UNAVAILABLE`。
- **⚠️ 潜在问题**：compose 未给 management-bff 覆盖 `WALLET_INTERNAL_URL`（application.yml 默认 `http://localhost:8083`）→ 容器内 merchant-wallet 代理会打到本容器 8083，**Docker 部署下商户余额/账单只读接口会 502**（宿主 IDEA 模式无碍）。同类问题已修复 payment 的 `WALLET_BASE_URL`，此处待处理。

### 7.2 转账 TCC 全链路（跨钱包分片）

```
payment @GlobalTransactional(wallet-transfer-v1)
  → 取 XID → identity.verifyAndConsume(TRANSFER_INTENT) 授权
  → wallet.tryDebit(payer, XID 头)        [钱包冻结+预留年度额度, 分支注册]
  → wallet.tryCredit(receiver, XID 头)    [不动钱, 只插 pending_credit]
Seata TC 提交 → RPC 回调 wallet confirmDebit(+TRANSFER_CLEARING) / confirmCredit(+收款人)
Seata TC 回滚 → RPC 回调 wallet cancelDebit(解冻) / cancelCredit
payment reconcile → wallet.transferOutcome 双状态判定 SUCCEEDED/FAILED
```

### 7.3 服务间调用

```
merchant-web(8001)/ops-web(8000) → management-bff(8088) → identity/payment/wallet
consumer(未来) → consumer-bff(8087) [脚手架] → identity/payment/wallet/agent
identity(8081) ←→ payment(8082) : OAuth client_credentials + verify-and-consume / merchant-owner
payment(8082) → wallet(8083) : 服务令牌 + TCC try + postings
seata-server(8091) : 全局事务 TC，回调 wallet TCC confirm/cancel
```
