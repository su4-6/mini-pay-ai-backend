# contracts 文件说明

本目录不是业务代码，也不会影响服务启动。它存放“前后端和服务之间如何通信”的协议说明；写接口前先看对应文件，接口完成后让代码、测试和文件保持一致。

## 截图中的文件分别做什么

| 文件 | 用途 | 开发时谁需要看 |
|---|---|---|
| `openapi/identity-api-v1.yaml` | 身份服务的公开接口：演示验证码、支付密码验证和一次性支付授权令牌。支付密码只允许进入 Identity。 | 登录/安全设置前端、Identity 后端 |
| `openapi/wallet-api-v1.yaml` | 钱包公开接口：钱包摘要、账单分页、演示充值。 | 钱包/账单前端、Wallet 后端 |
| `openapi/payment-api-v1.yaml` | 支付服务公开接口：创建转账意图、确认转账、查询转账、创建退款。 | 转账/退款前端、Payment 后端 |
| `openapi/agent-api-v1.yaml` | AI 助手公开接口：创建会话和接收 SSE 流。只允许查询、追问和确认卡，不能直接转账。 | AI 前端、Agent 后端 |
| `openapi/management-api-v1.yaml` | 运营/商户后台的公开查询接口：支付订单和退款订单列表。 | Ops/Merchant 前端、Management BFF/Payment 后端 |
| `asyncapi/events-v1.yaml` | RabbitMQ 事件信封：开户、转账完成、退款完成等异步事件必须包含的字段。 | 事件生产者和消费者 |
| `README.md` | 契约总规则：版本、金额、时间、错误格式、幂等和变更要求。 | 所有开发者 |

## 你写代码时怎么用

1. 写页面前：打开对应 `openapi` 文件，按 `paths` 找接口路径，按 `requestBody` 写请求字段，按 `responses` 处理成功和失败。
2. 写 Controller 前：先补齐或确认对应 YAML，再按 YAML 的路径、字段和状态码实现；不能私自增加前端依赖的字段。
3. 写 RabbitMQ 消费者前：看 `events-v1.yaml`，以 `eventId` 做 Inbox 去重，并校验事件版本和必填字段。
4. 字段、状态码或事件格式改变时：先更新契约，再更新前端 DTO/Mock、后端测试和联调记录；删除字段或改变字段含义必须做版本兼容。

## 必须遵守的通用规则

- 金额统一使用 `amountCent`，即“分”的整数；例如 `10000` 表示 ¥100.00，不能传浮点数。
- 所有会创建或改变交易的请求都要带 `Idempotency-Key`，避免重复点击造成重复扣款或重复退款。
- 成功响应直接返回资源；失败响应使用 `application/problem+json`，前端依据稳定的 `code` 处理，而不是解析错误文案。
- `/api/v1` 是客户端公开接口；`/internal/v1`、TCC、数据库和 RabbitMQ 不能被前端访问。
- 这些 YAML 当前是 MVP 的**设计契约**，不等于接口已经写完；具体实现进度以代码、测试和联调记录为准。
